# Security policy

## Report a vulnerability privately

Report a vulnerability in CrossLint through GitHub's private vulnerability reporting, never on the [forum](https://forum.setdef.com/c/crosslint), in an email thread, or anywhere else others can read it:

1. Open [the repository's Security tab](https://github.com/setdef/CrossLint/security) and choose **Report a vulnerability**, or go straight to [a new private advisory](https://github.com/setdef/CrossLint/security/advisories/new).
2. Fill in the form. Only the project's maintainers can see what you send.

If you aren't sure that a problem is a vulnerability, report it privately anyway.

## What to include

- The CrossLint version, from `crosslint --version`.
- Your system: its operating system and processor.
- How to reproduce the problem: the project's configuration and plugins, the command you ran, and what happened.

## Which versions get fixes

[The README's Versions section](README.md#versions) lists what each release keeps working. It makes no promise that an earlier release gets a fix. A fix ships in a new release, so install [the latest release](https://github.com/setdef/CrossLint/releases/latest).
